# Учёт личных расходов — ASP.NET Core + PostgreSQL

Проект подключается к существующей базе `MyDataBase` и использует таблицы:
`roles`, `users`, `categories`, `payment_methods`, `transactions`,
`change_requests`, `audit_log`.

## Что реализовано

- Вход и регистрация. Новые аккаунты получают роль «Пользователь».
- Авторизация через защищённую cookie.
- Разделение доступа: пользователь видит свои операции; менеджер и администратор — операции всех пользователей.
- Создание, просмотр, изменение и удаление финансовых операций.
- Фильтры по тексту, типу и датам.
- Проверка суммы, типа операции, категории и способа оплаты.
- Запросы на изменение и рассмотрение менеджером/администратором.
- Запись основных действий в `audit_log`.
- Защита от SQL-инъекций через LINQ/EF Core и параметризованные запросы.
- Анти-CSRF токены для POST-форм, проверка данных на сервере, хеширование паролей.

## 1. Настройка подключения

Открой `appsettings.json`. Замени `CHANGE_ME` на пароль PostgreSQL:
`Host=localhost;Port=5432;Database=MyDataBase;Username=postgres;Password=...`

Не публикуй пароль и не загружай его в GitHub. Для реального развёртывания используй User Secrets или переменные окружения.

## 2. Требования

- .NET 10 SDK
- PostgreSQL
- Доступ к существующей базе `MyDataBase`

Проверить SDK:
```bash
dotnet --list-sdks
```

## 3. Запуск

Открой терминал в папке проекта и выполни:
```bash
dotnet restore
dotnet run
```
Открой адрес HTTPS/HTTP, который покажет консоль.

## 4. Важно про структуру БД

Код сопоставляет поля по скриншотам:
- `users`: `id`, `role_id`, `full_name`, `email`, `password_hash`, `created_at`
- `transactions`: `id`, `user_id`, `payment_method_id`, `category_id`, `type`, `amount`, `description`, `transaction_date`, `created_at`
- `change_requests`: `id`, `transaction_id`, `user_id`, `request_text`, `status`, `created_at`, `reviewed_by`, `reviewed_at`
- `audit_log`: `id`, `user_id`, `action`, `name`, `details`, `created_at`

Перед запуском проверь, что имена столбцов совпадают. Приложение не создаёт и не удаляет таблицы и не запускает миграции.

## 5. Подготовка существующих пользователей

В `users.password_hash` должны храниться хеши ASP.NET PasswordHasher. Старые демонстрационные значения вроде `test_hash_1` не являются действующими паролями для этого приложения. Зарегистрируй новый аккаунт через форму — ему назначится роль «Пользователь».

Чтобы назначить аккаунту роль менеджера или администратора, выполни в pgAdmin (замени почту):
```sql
UPDATE users
SET role_id = (SELECT id FROM roles WHERE name = 'Админ')
WHERE email = 'admin@example.com';
```
Для менеджера используй `'Менеджер'`, для обычного аккаунта — `'Пользователь'`.
Делай это только для доверенных аккаунтов. Не назначай роль администратора через публичную регистрацию.

## 6. Пункт 10 — защита

1. EF Core LINQ формирует параметризованные SQL-запросы. Не склеивай SQL из пользовательского ввода.
2. Для ручного SQL используй `FromSqlInterpolated`/параметры, а не конкатенацию строк.
3. Пароли хранятся в виде хеша через `PasswordHasher`, не в открытом виде.
4. Доступ к контроллерам ограничен `[Authorize]` и политиками ролей.
5. Проверяется принадлежность операции текущему пользователю.
6. POST-запросы защищены `ValidateAntiForgeryToken`.
7. Входные данные проверяются на сервере, значения списков сверяются с БД.
8. Ошибки не должны показывать пользователю строку подключения или пароль БД.
